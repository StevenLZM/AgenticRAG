# Research 终止策略设计

日期：2026-10-10

状态：待用户审阅，尚未实施。

本次只调整知识库问答的继续和终止策略：无事实进展时停止无效检索，执行前检查剩余预算，并向用户返回与真实停止原因一致的说明。保留现有 Fast RAG 和 Research 路由、Research 规划职责、检索算法和答案审核链路。

## 范围与成功条件

本次包含：

- 在新检索批次完成后自动评估证据，不必等待主模型主动提交证据。
- 根据事实覆盖变化判断无进展，服务端控制是否继续。
- 在模型调用和检索执行前检查剩余时间及动作预算，保留收尾时间。
- 对资料不足、预算耗尽和技术故障给出不同的公开终止说明。
- 必要的状态持久化、接口兼容、日志与回归测试。

本次不包含：合并 Fast RAG 与 Research 路由、增加统一业务编排器、增加 Fast RAG 独立补查循环、让 Grader 生成检索 query、改造 Todo 规划算法、增加工单或其他写入工具、扩展 Tool 或 MCP 权限体系、修改切块或索引、重建 ES 或 MySQL 数据。

成功条件是简单的无资料问题不再耗尽所有研究动作，有效多跳检索不因片段重复而误停，技术故障不被解释成资料不存在。现有答案引用和忠实性审核不放宽。本次不增加“证据不充分也自动生成部分答案”的能力。

## 当前问题

`research_loop.py` 每次执行一个主模型动作。创建 Todo、检索、提交证据都消耗 `research_attempt_count`，但这个计数不代表有效检索轮数。循环入口达到上限就停止，缺少对新动作是否仍有完成价值的检查。

`graph.py` 主要在 Research 提交证据后执行 Grader。新检索结果即使只重复了无关内容，也可能先经历更多主模型规划或提交动作。

`routing_policy.py` 对一般的证据不足主要依据动作次数决定是否继续，没有事实进展状态。`EvidenceGrade` 只有 `decision`、`gap_type` 和自由文本 `gaps`，不能通过比较缺口字符串或片段数量可靠判断进展。

Worker 有总超时保护，ModelGateway 已在单次结构化操作内共享重试和修复预算，但二者尚未共同约束整次研究的剩余时间。前端现有 `cannot_answer` 文案也不能区分资料不足与其他失败。

## 选择的方案

采用独立的服务端终止策略函数，嵌入现有图和 Research 循环，不新增 Router 路线。

只降低动作次数上限虽然改动小，但会同样截断正常多跳任务；只让主模型自行决定停止仍然依赖昂贵的下一次模型调用。两者都不能替代基于证据进展和剩余预算的服务端判断。

职责保持如下：

| 组件 | 本次职责 |
| --- | --- |
| Evidence Grader | 判断证据是否足够，报告缺口及有出处的事实覆盖变化 |
| 终止策略函数 | 根据评估结果、历史进展、服务状态和预算返回继续、生成或终止 |
| Research | 在允许继续时使用原有规划和检索工具选择下一步，仍负责生成 query |
| Worker 与 ModelGateway | 提供并执行不可重置的运行截止时间和单次调用限额 |
| 公开结果投影与前端 | 显示安全、明确、持久化的终止说明 |

## 证据进展状态

为新版策略增加版本化的 Grader 输出和 checkpoint 状态，不以自由文本 `gaps` 的措辞变化作为进展。

首次成功评估形成与用户问题对应的事实要求集合，由服务端分配稳定的 `requirement_id`。之后的评估必须引用已有 ID，不能通过重命名要求重置进展。必要的多跳中间事实记录到已有要求下，并关联具体依赖任务，不因新建 Todo 自动成为新事实要求。

每项覆盖记录包含：

- `requirement_id` 和 `status`，状态为 `missing`、`partial` 或 `supported`。
- 支持该要求的原子事实，以及每个事实的 `evidence_ids` 和可定位的 `supporting_spans`。
- 必要时关联的中间依赖任务 ID。

Grader 比较先前已接受的事实与当前证据，报告新增或修正的事实。服务端校验要求 ID、证据 manifest、片段出处和批次归属；原文定位只能证明出处存在，语义支持和新颖性仍由 Grader 判断，不能声称代码校验完全消除了模型误判。

有效进展包括首次补上缺失事实、为部分事实补全必要条件，或获得可用于下一跳的已验证中间事实。新 parent ID、更多候选片段、更多 Todo、同一事实的改写或另一份重复出处，都不构成进展。

保存每个已评估批次的服务端 ID、事实覆盖版本、连续无进展计数和查询指纹。同一批次的重放不能重复累计计数。创建或更新 Todo 不清零计数。事实出现矛盾时撤销不再成立的支持，不把矛盾本身当作证据充分，也不删除历史进展记录。

## 自动评估与早停

Fast RAG 仍只执行现有的一次检索和评估，其正常评估结果可作为进展基线。证据不足时仍进入现有 Research，不增加 Fast RAG 补查流程。

Research 每次直接检索或并行委派完成后，先聚合并验证结果，再进入 Evidence Builder 和 Grader。一次并行委派聚合后算一个逻辑批次，不能把三个并行查询算成连续三次无进展。没有新检索结果的计划动作不触发额外评估。

已经评估的相同证据版本可以复用结果，`submit_evidence` 不再重复调用 Grader。足够回答原问题时进入原有生成和审核链路，不再要求模型完成无必要的规划动作才能收尾。Todo 的任务状态不等于答案充分性，尚未完成的原问题要求仍由 Grader 检查。

默认连续无进展阈值为两个健康、成功评估的逻辑批次。首次批次没有任何有用事实时计数为一；首次有事实进展时计数为零。出现有效事实增益则清零。早停同时要求至少完成一次面向未解决缺口、区别于首轮查询的正常 Research 检索；新 query 的文本不同并不自动证明它有效，目标要求必须匹配且需要正常评估。

首次未命中本身不触发无进展终止。没有新意的重复查询可以被策略拒绝，但不伪装成已经完成一次健康补查；无法构造可执行的新检索时按“未能补齐证据”收尾，不据此断言语料不存在。

对于多跳任务，计数对应当前缺口及必要依赖的检索进展，不因单个分支失败而停止整个任务。若仍有此前未评估的必要就绪任务，且预算允许，先执行该任务；不能靠反复新增没有事实依据的 Todo 重置计数或无限延后终止。查询去重、既有 Todo 数量上限和动作预算共同约束这种情况。

检索或评估失败不计入健康无进展批次。并行检索部分失败时保留成功证据；如果失败分支覆盖尚未解决的必要要求，不得把整体结果标为资料未找到。失败走现有受预算约束的恢复或技术错误终止。

决策优先级固定为：取消、权限拒绝及无效状态先处理；最新有效评估已充分且仍有收尾时间时优先生成；未解决的必要技术故障单独处理；满足健康无进展条件时停止研究；否则检查时间及动作预算，允许继续才返回 Research。多个上限同时触发时保存实际触发条件，但公开说明只使用已有证据能够支持的分类。

## 剩余预算与收尾

保留现有 `max_research_rounds` 动作上限，本次不改名或重新解释历史计数。新增的健康检索批次计数只用于早停，自动评估不消耗主模型动作次数，但消耗运行时间和模型调用成本。

每次 Run 使用服务器持久化的首次执行起点建立绝对截止时间。首次执行起点沿用数据库首次 claim 保留的 `started_at`；入队到首次 claim 的等待单独记录，首次 claim 后的并发槽等待、重投等待和恢复时间都计入预算。Worker 重新 claim 或 checkpoint 恢复不能得到一份新的完整预算。

运行截止时间通过受信任上下文传递，模型和用户不能覆盖。进程内根据绝对剩余时间建立单调时钟超时；检查 Worker、模型及工具已有截止时间时只能取更早值。若时钟异常导致剩余时间无法可靠计算，停止执行并给出技术错误，不延长截止时间。

新版策略默认收尾预留为总执行预算的 20%，最多 60 秒，作为待回归验证的初始配置，而不是延迟承诺。只有剩余研究时间至少为 5 秒时才允许启动新的研究调用。生成及审核可以使用收尾预留，但仍受总截止时间约束。

研究操作可用时间为：

`min(原有单次调用上限, Run 剩余时间 - 收尾预留)`。

ModelGateway 的重试、结构化修复继续共享同一操作截止时间，不额外获赠预算。并行任务的排队和执行都必须被父级剩余时间覆盖。达到研究软截止后停止启动和继续等待研究工作，在保留的时间内生成经审核答案或持久化终止说明。

动作预算还需要前置约束：剩余一个动作时，不允许再创建需要后续动作执行的新计划；可以执行已就绪的最终检索，再由自动评估决定是否生成。证据已充分时，不因研究动作数刚好达到上限而丢弃正常收尾机会。已经取消或超出总硬截止的 Run 不再启动生成。

资料不足等终止说明由服务端模板生成，不增加主模型调用。可选的记忆提取不占用关键的结果持久化时间；终止分支跳过可选提取，正常成功分支的记忆行为不在此次重构范围内。Worker 最终状态写入继续受既有 lease 和 claim generation 保护。

## 终止结果与展示

内部停止原因和面向用户的语义分开。`research_no_progress` 表示为什么停止研究，不等价于“整个知识库没有资料”。公开结果新增可选的受控 `notice`，只包含服务端枚举 `code` 与对应模板 `message`。

| 公开说明类型 | 使用条件 | 默认说明 |
| --- | --- | --- |
| `knowledge_not_found` | 正常检索和针对性补查均未找到支持问题的事实 | 在当前可访问资料的本次检索中，未找到支持这个问题的信息。请补充相关资料后再查询。 |
| `evidence_insufficient` | 有部分支持，但仍不足以回答；或未完成足以判定未找到的补查 | 现有证据不足以完整回答这个问题，本次检索未能补齐所需信息。 |
| `budget_exhausted` | 达到时间或动作预算，尚未完成充分检索或回答审核 | 本次查询已达到处理预算，未能完成回答；这不代表资料不存在。 |
| `retrieval_unavailable` | 必要检索服务失败，无法完成核实 | 检索服务暂时异常，本次未能完成查询。 |
| `evidence_grader_unavailable` | 评估失败，不能判断证据覆盖 | 证据评估服务暂时异常，本次未能完成核实。 |

取消、权限拒绝和状态损坏沿用独立的安全处理，不能用资料不足覆盖它们。足够回答的问题继续使用原有生成、忠实性和引用审核。此次资料不足分支只返回说明，不增加自动部分回答，不把 Grader 的推理或 Research 草稿直接放进公开 `segments`。

`notice` 不表示文档事实经过审核，不设置虚假的 `audited=true`，不通过改成 chat route 绕过审核。沿用现有 `status` 能表达的分类：资料不足对应 `cannot_answer`，动作上限保留 `research_round_limit`，新增停止细节由受控原因及 notice 表达。系统崩溃、取消和总硬超时仍保留原有生命周期状态，不能统一改成正常完成。

公开投影必须验证 notice 与终止原因的一致性。API、SSE 最终结果和重开会话均读取同一份持久化公开结果。前端优先展示已验证 notice，没有 notice 的历史结果继续使用旧状态文案；不得因此放开未审核内容显示。

## 版本兼容与变更边界

为新建 Run 增加可选的版本化终止策略配置，包含无进展阈值及预算参数，写入不可变 snapshot 和评测身份。旧 snapshot 缺少该配置时维持旧 hash 和旧策略，不在升级时静默改变运行中的任务。新增配置和状态均使用现有 JSON 持久化通道，不要求业务表结构迁移。

新版 Grader 输出必须由明确的策略和 prompt 版本选择。旧 Grader 的自由文本缺口不足以支撑语义早停：不能假装已有进展数据，也不能默认判为零进展。新策略遇到无效输出时按评估失败处理。

主要涉及 `query/graph.py`、`research_loop.py`、`routing_policy.py`、`state.py`、Grader 契约及提示词、运行预算传递、公开结果投影和前端状态说明。`fast_rag.py` 仅接入已有评估结果的进展基线及剩余预算。检索算法、Research 的 query 生成和工具适配器不改。

不覆盖工作区已有的 Router、相关测试及评测进度文档改动。实施时对重叠测试做增量修改，独立记录本次修改范围，不打包其他未提交内容。

## 验收与回退

必须覆盖以下自动化场景：

1. 首轮和一次针对性补查都无支持事实，及时早停并显示资料未找到。
2. 首轮未命中、补查成功，正常生成并通过审核。
3. 候选 parent 数量增加，但事实覆盖没有变化，仍判无进展。
4. 新中间事实使多跳任务可继续，或其他必要分支尚未执行，不被误停。
5. 新建 Todo、同义改写缺口、重复批次重放不能重置或重复累计进展。
6. 一次并行委派只产生一次批次评估；部分服务失败不冒充资料不存在。
7. 最后一个动作不再开启新计划，最后一次检索发现充分证据仍能收尾。
8. 研究超时、模型修复、并发排队和恢复共用剩余预算；重投不能延长截止时间。
9. 终止说明不调用生成模型、不依赖记忆提取；结果持久化后可通过 API、SSE 和重开会话一致读取。
10. 旧 snapshot、旧 checkpoint、旧公开结果保持可读且策略不被静默更换。
11. notice 不能携带任意模型草稿，不改变现有引用及忠实性审核约束。

真实模型回归分别统计无资料问题耗时、正常问题成功率、多跳误停率、有效事实增益和停止原因。默认阈值及时间预留需要结合回归结果评估；不能仅凭模拟测试宣称首 token 或总耗时达到某个生产指标。

新策略通过服务端新建 Run 配置启用；关闭后新 Run 使用旧策略，已存在的 Run 按自身 snapshot 执行。回退代码前先停止接收新版 Run 并等待其结束，避免旧程序读取不认识的新字段。此次无需回滚文档索引或语料数据。
