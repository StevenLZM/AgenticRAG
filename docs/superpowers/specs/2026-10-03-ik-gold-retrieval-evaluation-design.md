# IK 金标重绑定与检索对照测评设计

日期：2026-10-03。状态：用户已确认本设计；详细实施计划待审阅和选择执行方式，尚未进入实现或测评执行。

本设计覆盖第一批工作：复用正式上传文档的原文事实，把现有金标安全绑定到 index-v4，冻结真实分词环境，并比较同一索引上的 standard 与 IK 混合 BM25。目标是区分“标签是否仍有效”和“中文检索是否改善”，不预设 IK 必然提高分数。

不重新生成、上传、分块或嵌入文档，不从检索结果反推正确答案，不覆盖旧金标、评分说明、Run 或成绩。第一轮真实对照只执行 ES 分词和 BM25 请求，不调用回答模型、Embedding 或 Judge，也不提交 Query Run。完整检索链路和端到端问答在后续有明确预算的阶段执行。

## 范围与边界

### 本批交付

1. v3 到 v4 的原文、分块和标签等价性审核，以及新目录中的绑定版本。
2. 可追溯的词法环境清单和前后两次漂移检查。
3. 同一 v4 索引上的 standard 与 IK 混合 BM25 配对测评，以及逐题、分类、宏平均报告。
4. 后续组合检索与真实问答可复用的实验身份和恢复契约。

### 后续批次

自然中文问法和困难负例、增量真实文档标注、人工金标审核、事实级 Judge 校准、Dense/RRF/rerank/Parent/最终上下文对照、候选预算优化、完整 validation/test、持久化聊天与工具场景，均保留为后续批次。

本批不修改正式检索默认权重和候选数，不写 SQL/ES 业务数据，不切 alias，不修改生产配置或启动/停止服务，不自动批准审核、选参或发布。单元测试可以使用固定样本验证契约，但这些结果不得冒充真实检索质量。

此前用户要求在 `real-rag-evaluation` 分支实现。当前文档保存在共享工作区，不自动提交到 main；实现计划必须安排安全地将已确认的主分支基线同步到评测分支，保留其他改动，不直接在旧代码上运行新的 IK 评测。

## 设计选择

只替换 snapshot_id 改动最小，但不能证明原文和证据未变化；重新生成全部问题答案则会破坏历史可比性。选择中间方案：保留题目与标签，先证明内容等价，再发布新的绑定和运行环境清单。

第一批继续兼容 `GoldCaseV2`，不同时重写所有金标结构。通过独立清单区分内容身份、索引身份和实验身份；后续新增语义金标格式时另发版本。

## 金标重绑定契约

### 先证明内容等价

重绑定工具只读取已有原文、SQL、ES、Artifact 和 journal，输出新评测文件。必须确认：

- 同一用户范围、相同文档和版本集合；原文件 SHA256、AST 哈希及解析、分块、Embedding 版本不变。
- Parent ID、内容、顺序和完整有效行数据不变；Child ID、Parent 关系、正文、上下文、向量、位置等内容不变。
- 仅允许本次迁移已定义的变化：索引代际、具体索引/UUID、文档版本的 manifest 路径/哈希，以及 manifest 内的 index_generation。必须解析 manifest，证明其余内容相同，不能只忽略 manifest 哈希差异。
- 索引配置变化单独归入词法环境，不算作答案事实变化。用户归属、发布状态和过滤条件变化不能作为分词实验豁免。
- 对所有文档核验，不只核验题目引用的文档，避免干扰文档增删悄悄改变结果。

若发现新增、删除、重传、重新分块或内容变化，输出差异并停止“等价重绑定”。这需要新的语料修订与标注处理，不能静默忽略变化或丢弃失效题。没有权限或无法读取某项证据时保持未验证，不以计数相同代替内容相同。

### 迁移题目及评分说明

为全部 4453 题创建新绑定，严格保留题目顺序与所有非绑定字段，包括 case_id、问题、参考答案、事实组、原文锚点、关键字段、计算过程、证据充分集合、split、question_family、graded qrels 和 review_status。题目仅更新 snapshot_id；生成稳定的“排除 snapshot_id 后整条题目”哈希，证明其他字段完全相同。

对每条 Child/Parent 引用重新验证用户和文档版本范围，并用既有原文锚点与 AST 规则复核充分性。1 个 unmapped 事实保持原标签及分母，不能因检索器改变而自动认定 mapped。

评分说明同时更新 snapshot_id 与 gold_case_sha256。required_facts、optional_facts、supporting_facts、source_refs、critical_rules、问题条件及审核状态必须逐字段与旧说明一致。可用当前确定性构造器重建后比较，但发现分句、规则或语义差异时必须停止，不能借迁移修改评分标准。

所有新产物使用独立目录；旧文件字节和哈希不变。输出 `rebind-audit.json`，记录源/目标输入哈希、journal 哈希、明确的规范化白名单及版本、等价性核验结果、允许的差异、题目和事实计数、映射状态以及拒绝原因。中断目录标记 incomplete，未完成全部验证不能用于正式实验。重复输出不得覆盖已冻结目录。

## 分词环境清单

新增独立词法环境清单，不将插件、词典或查询权重混入正确答案。环境记录至少包括：

- ES 与 Lucene 版本、cluster UUID、目标物理索引 UUID、alias 定义及路由/过滤配置。
- 实际 mapping、相关 settings，包括 analyzer、search_analyzer、相似度及影响检索的设置；不只记录期望配置。
- 所有相关节点的 IK 版本，插件包或实际安装制品的哈希、有效词典和配置的哈希，以及远程词典启用状态。实际文件不可获得时明确标记来源与缺项，版本字符串或 `_analyze` 探针不能替代完整性证明。
- 程序内固定、版本化的探针输入和 standard、ik_max_word、ik_smart 的 token/position/offset 输出及哈希。探针覆盖中文短语、未登录词、中英文混合、金额日期和重复短词；不把精确 token 数当质量分数。
- 源代码提交及实现哈希、采集时间、取证方式。不得保存凭据或未经脱敏的连接串。

环境清单独立内容寻址，两组实验必须引用同一个已验证的清单哈希。运行前后都核验环境、内容与 alias 未漂移。缺少必要环境证明时可以输出分词诊断，但不标记严格 A/B 已验证。远程词典、插件或配置变化需要新环境身份；本批不安装插件、调整词典或启用词典在线更新。

旧隔离 allocation 默认 standard，不能把 9201 的旧成绩标为 IK 成绩。本批目标显式绑定正式 v4 数据和现有用户范围，禁止命令缺参时静默退回旧隔离语料。

## 配对实验契约

### 两组只改变词法查询方式

| 组别 | 目标数据 | BM25 查询 |
| --- | --- | --- |
| A | 同一 v4 物理索引和代际 | standard 根字段 match |
| B | 同一 v4 物理索引和代际 | 当前 IK 双字段 best_fields，权重 2 比 1 |

两组使用相同金标、新快照、词法环境、题目顺序、查询原文、用户/active/generation 过滤、候选上限、请求超时和实现版本，不进行 query rewrite。两组都不向 BM25 增加原请求以外的公司或年份过滤，否则实验同时改变了查询语义。显式记录实际 operator=OR、字段权重和 tie_breaker；IK 分词不等于实体必选条件。

配对实验清单保存共同身份、两组配置、实际 DSL 及各自完整指纹，并明确允许变化的 lexical profile 与关联查询字段/权重。必须用可审计的脱敏配置及组件哈希重算身份，不能直接跳过整个 provider/runtime 哈希检查。只有声明的差异允许通过；换模型、换语料、换预算、换代码均拒绝归入本次对照。

现有 `tuning._comparable` 和旧 resume 的严格规则继续保留。新增词法配对比较器，不给旧比较器增加“忽略指纹”的开关。也不将纯检索报告伪造成缺少答案字段的正式问答报告去参加 Pareto 选参。

### 第一轮运行方式

默认使用 dev 中每类 20 题，共 100 题；按固定协议 `ik-bm25-paired-v1` 与 case_id 的哈希顺序确定性抽样，题号写入清单。样本不足时拒绝，不从 validation/test 补齐，也不按得分挑题。该题集只是现有模板金标的分层诊断，尚不代表自然中文质量。

BM25 两组候选上限均为 40，与当前系统默认候选预算一致。逐题相邻执行两组，以确定性规则交替 A/B 先后，避免固定先后顺序的缓存偏差。排名保留 ES 实际返回顺序；相同分数也不自行按 Child ID 重排，保留全部原始名次并披露并列名次可能波动的限制。原始 BM25 分数只用于排查，不跨两种查询方式比较绝对分值大小。记录实际耗时，但单次本地结果不作为生产 P95 容量结论。

直接调用项目真实 Elasticsearch BM25 adapter，目标固定到预检验证的物理索引；保留相同服务端过滤逻辑。只做 ES 只读检索与分词，不调用 Router，不提交 Query API，不重启生产服务。首轮默认并发 1、检索请求预算 200、每请求超时 30 秒、检索阶段墙钟预算 900 秒；预检读取与分词探针另行计数并设置有界超时。恢复预算包含历史尝试；失败写账本，超出预算保留 pending，不无限重试或反复抽样至更高分。

第一轮不请求 Dense、Embedding、reranker、生成模型或 Judge。报告这些阶段为 not_executed，绝不根据 BM25 结果推算 RRF、答案正确率或完整 RAG 成绩。

后续组合检索 A/B 应按相同 query 和 Embedding 模型获得真实向量与 Dense 候选，在两臂间复用同一份已验证输入，再分别进入真实 RRF、rerank、Parent 和最终打包逻辑。缓存命中与新增调用分别记账。此扩展需要独立预算与执行批准；不能用不明来源旧向量或模拟排名替代。

### 结果和恢复

逐题持久化实际请求、返回 ID/排名/分数、作用域、耗时、完整请求身份及状态。结果目录权限沿用现有受限 Artifact 规则，公开报告不放个人原文。已完成请求通过一致性验证后复用；恢复时先重新预检，不把缺失账本当成从未执行。

请求未确定完成时保留 uncertain；本批不自动重发。ES 只读调用的人工重试如获批准，需新增 attempt 并保留原尝试，不能覆盖失败到满意结果。两臂只完成一侧时不得给该题计算已验证配对差值，也不能从总分母静默删除。

同输入、代码及环境下完整 resume 应新增 ES 检索请求为 0；预检的读取与分词探针单独计数。禁止新增 Query POST 和模型调用。环境漂移时拒绝恢复，输出原因并保留历史结果。

## 指标与报告

每组输出 Child Recall@K、fact recall、完整证据覆盖率、MRR@40 与 binary NDCG@K，K 使用 1、3、5、10、20、30、40。只能报告请求窗口支持的 K；返回不足 K 条是真实结果，不补假候选、不缩小金标分母。

沿用证据集合内 AND、集合间 OR 和全部必需事实覆盖规则。含 unmapped 事实的题继续使用现有 qrel_unmapped/null 口径，报告其总量及评分覆盖率，不把无法标注直接算成检索得零分。不存在人工等级标签时，graded NDCG 保持 N/A；即使部分标签存在，缺少完整前缀和可信理想排序标注也不能宣称分级排名已完成评价。召回的其他文档若没有人工无关标注，只能报告“未命中已标注证据”等诊断，不能全部当作已证明无关的 hard negative。

报告包含：

- 两组绝对分数、同题差值、提升/不变/退化题，以及代表性失误的证据 ID。
- 按题型、来源格式分组的结果与宏平均；清楚显示每类样本数，避免章节题数量掩盖其他类别。
- 总样本数、有效请求数、有效配对数、失败/unknown 数；失败保留在覆盖率及保守结果的分母。
- 原文事实映射有效性与已知解析缺陷，不把“分块本来没有证据”归因于分词器。
- 实际请求数、超时、每组耗时、前后环境核验状态、语料和实验身份。

分词探针、检索指标、系统运行成功率和答案质量各自命名，不合成为模糊的总分。第一批一律 `eligible_for_tuning=false`、`production_release_accepted=false`；人工审核和裁判校准门槛保持不变。

## 与后续完整测评的连接

新绑定可供现有 formal v2 真实问答入口使用，但必须创建新的 Run 和实验目录；旧回答回放只用于验证评分器。IK 与主分支 Research 修复的效果要通过固定主分支代码下的对照区分。

下一批补充自然中文题、版本/实体干扰项和对应 question_family，原题的等义改写保持同一 split。新增内容不原地混入本批基线，必须新发数据版本并核验原文。

人工审核与事实级校准完成后，再固定词法方案逐级比较候选数量，最后执行 validation 选方案和 held-out test 验收。多轮会话与工具另用场景契约；不得绕过现有 chat-session 对 evaluation 的拒绝，也不得混用文档上下文评判外部工具事实。

## 验收条件

1. 所有源金标、评分说明和旧实验文件哈希不变；新 4453 题非绑定内容与原题完全相同，split 和 1 个 unmapped 事实保留。
2. 任一原文、版本集合、Parent/Child 内容、向量、AST、用户或发布状态非预期变化，均阻止等价重绑定。
3. 分词配置、mapping、插件或词典证据缺失/漂移不能得到严格验证通过；单看 UUID 和 token 探针不够。
4. A/B 只允许指定词法查询变化；模拟改变预算、作用域、代码、题集、语料或其他配置时比较器必须拒绝。
5. 在可丢弃测试 ES 上验证协议；随后只读真实 v4 对照记录实际请求与结果。固定样本只用于单元契约，不计真实质量成绩。
6. 未执行的 Dense、RRF、rerank 和答案阶段明确显示 not_executed；不足请求窗口的 K、未标注 graded qrels 不伪造得分。
7. 中断不覆盖原尝试，失败不静默删除；同配置完整恢复新增检索请求为 0，所有阶段 Query POST 和模型调用均为 0。
8. 输出可读报告、新输入绑定和恢复说明；仅标记工程与数据绑定是否通过，不自动发布参数或声称 IK 提升、生产验收通过。
