# 回龙观到王府井：真实高德 MCP 测试

日期：2026-10-02。原始 query：`回龙观到王府井的公共交通路线`。

**初次测试结论：真实调用成功，公交结果展示不完整；该问题随后已修复，见本文末尾复验记录。** 初次测试仅验证、定位和记录，没有修改业务源码。

使用最新工作区代码、已配置真实模型及用户指定高德 SSE 服务；没有 mock。执行路径为 Router → Fast RAG 共享动作循环 → ToolRuntime → McpAdapter → 高德，再进入确定性公开结果构建。

## 实际调用

共 6 个动作：2 次工具发现、2 次 maps_geo（回龙观、王府井）、1 次 maps_direction_transit_integrated、1 次 finish。模型自动选择北京，公交调用的 city/cityd 均为北京。高德返回 5 条方案，最终成功生成 5 张 mode=transit 卡片，tool_audited=true。

例如上游第一条方案包含：步行至龙泽 → 地铁 13 号线到霍营 → 地铁 8 号线到金鱼胡同 → 步行到目的地；返回耗时 4661 秒、步行距离 1843 米。这些是本次查询时供应商的估算。起点使用高德对“回龙观”的地理编码结果，没有额外假定用户指定回龙观地铁站。

## 定位到的缺口

公开卡片只有“公交路线 1…5”、耗时、起终点坐标和高德导航链接，未展示线路名称、上下车站和换乘步骤。

根因位于 `src/agentic_rag/query/tool_answers.py` 的 `_route_cards`：当前仅解析 `path.steps[].instruction`，真实公交方案将分段放在 `transits[].segments[]`，线路位于其 `bus.buslines[]`，步行在 `walking` 中，因此上游事实在领域投影层被丢弃，未进入公开结果。这不是高德缺少数据或鉴权失败。

后续需补公交分段的领域投影及真实结构回归，再验证文字、卡片详情和历史恢复。不能仅凭 tool_audited=true 和卡片数量认定公交业务体验已完整通过。
