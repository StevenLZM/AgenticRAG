# 统一工具层与高德 MCP 验证记录

日期：2026-10-02。分支：main。关联设计：[统一工具发现与执行层](../superpowers/specs/2026-10-02-unified-tool-runtime-design.md)。

## 交付范围

- Chat、Fast RAG、Research 共用 ToolRuntime；渐进式发现后调用，不新增 MCP 路由。原生检索、计算以及 Research 子任务使用同一预算和作用域。
- 支持 MCP Python SDK 1.26.0 的 SSE、Streamable HTTP；服务配置、none/bearer/header 鉴权、凭据解析与模型参数分离。高德只开放配置批准的只读工具。
- SQLite 调用记录保存同 Run 的预算、定义/参数摘要和可恢复结果；调用重复、取消、超时、子任务中断、凭据或目录变化均有回归覆盖。
- 文档审核与工具领域校验分别执行；混合回答缺少可解释的必要外部结果时不能静默发布文档部分。地点/路线卡片、来源、官方链接和折叠详情进入公开回答及会话历史。
- 会话按用户与 Session 隔离，引用保留可见序号、POI ID 和坐标；长期记忆作用域未变。
- 配置示例在 `.env.example`；真实凭据仅在已忽略的 `.env.local`，权限 0600。扫描版本控制候选文件未发现该凭据。

## 真实服务联调

已使用用户指定 SSE 地址及服务端 Bearer 鉴权完成认证、目录发现与只读查询。服务返回 9 个获准工具，覆盖地点搜索/详情、地理编码、周边、距离以及多种出行路线。

真实模型经现有 ModelGateway、Router、共享动作循环和真实 McpAdapter 连续完成三轮：

1. “查一下杭州东站，给我两个地点结果。”——发现工具、地点搜索、最终生成 2 张卡片及 POI ID 链接。
2. “上轮第一个地点的详细地址和坐标是什么？”——从会话引用取得相同 POI ID，按 ID 查询详情，输出 1 张包含真实坐标的卡片。
3. “从刚才的杭州东站到杭州西湖断桥，怎么驾车？只给一条路线。”——继续使用起点坐标，地理编码目的地并调用驾车工具，输出 1 张路线卡片，距离、耗时、路线步骤和导航 URL 均来自校验后的业务数据。

三轮最终动作数分别为 3、3、6，均通过工具结果校验。额外核实 DashScope 地理编码使用 `results` 包装且可能不含 formatted_address，已补专门回归；缺失完整地址时不编造街道门牌。

早期模型调用曾返回 JSON 后附加 DSML 标记，被严格校验拒绝。保留失败关闭与一次结构修复边界，补充纯 JSON 动作约束和确定性温度；最终三轮联调成功。少量成功调用不能代替模型质量评测或供应商稳定性保证。

该联调直接运行真实模型、路由和工具执行边界，使用隔离的本地调用日志；没有将测试对话写入用户现有会话，也未宣称完成真实 API → Redis → Worker → MySQL 的部署级端到端验收。

## 独立审查及修复

| 发现 | 修复和验证 |
| --- | --- |
| 子任务超时/Worker 中断永久取消整个 Run | 仅撤销当前调用 token 与租约，保留预算/截止时间；同调用恢复、父子独立、关闭重开均通过 |
| 混合回答把协议成功误当成有效外部事实 | 必要外部结果先做领域投影；真实图回归分别验证无效结果拒绝、有效结果保留双审核和文档引用 |
| 本地目录掩盖相关 MCP 的鉴权失败 | 无匹配时保留相关服务结构化错误；本地工具和无关服务独立使用 |
| 工具后控制回复循环 | 控制回复明确结束，图级澄清复现恢复且只完成一次记忆收尾 |
| 无鉴权服务配置失败 | auth_type=none 不创建凭据绑定，组合测试通过 |

## 首期限制与走查边界

- 当前为单 Worker、平台凭据、只读工具。用户 OAuth、写工具、跨服务共享密钥的聚合配额及多主机配额尚未实现。
- MCP 每次操作建立独立 SDK session、重新读取目录；保证权限检查与资源隔离，尚未做连接池、目录缓存和压力优化。
- 公开领域投影当前支持高德及本地计算；新增服务除注册 MCP 配置外，还需接入对应结果校验/展示契约。
- 未进行长时间压力、断网恢复或真实多用户登录验收。
- 本次未重启已有 8000 API/Worker，也未提交或推送本次改动。代码留在 main 工作区，原有 tmp/ 保留本地。
